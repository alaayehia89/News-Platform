
## 4. الحلول التقنية وأمان النظام (Technical Strategy & Security)

### إدارة الجلسات والصلاحيات (Authentication & RBAC)

* **المصادقة الهجينة (JWT Authentication Architecture):**
* يتم الاعتماد على رمز **JSON Web Token (JWT)** لتوفير صلاحية الوصول للـ API بدون حالة على الخادم (Stateless).
* تشفير الرمز باستخدام خوارزمية `HS256` وإدراج المكونات التالية في الـ Payload: `userId`, `roleId`, `email`.
* يتم حظر الرموز المنتهية عبر حفظ تاريخ تسجيل الخروج في الجدول أو تطبيق إستراتيجية Refresh Tokens عبر `HttpOnly Cookie` لضمان عدم وصول سكريبتات الشاشة (XSS) إليها.


* **التحكم بالوصول القائم على الأدوار (Role-Based Access Control - RBAC):**
* **Admin:** صلاحيات كاملة على النظام وإدارات المستخدمين والسجلات وتهيئة API.
* **Editor:** إنشاء، نشر، تعديل، أرشفة المقالات، إدارة العاجل، وتدقيق التعليقات.
* **Reporter:** كتابة الأخبار والتقارير وتحميل الوسائط بدون تفعيل قرار النشر المباشر (تظل بحالة `draft` أو `pending_review`).
* **User:** تصفح الموقع، التعليق، التفاعل، وحفظ المفضلة.

### نظام رفع الوسائط (Multer Pipeline & Storage)

* **هيكلية التخزين الموزعة:**
يتم توزيع الملفات داخل المجلد `public/uploads/` وفق تقسيم زمني لتفادي تكدس آلاف الملفات داخل المجلد الواحد:
`public/uploads/YYYY/MM/filename-uuid.ext`
* **آلية التسمية الفريدة والتصفية:**
توليد أسماء الملفات باستخدام **UUID v4** متبوعة بالامتداد الأصلي لمنع تعارض الأسماء والتغطية الحادّة على الملفات القديمة.
* **تصفية أنواع الميمات (MIME Type Validation):**

```javascript
const multer = require('multer');
const path = require('path');
const crypto = require('crypto');

// تحديد الامتدادات وأنواع الملفات المقبولة
const ALLOWED_MIME_TYPES = {
  'image/jpeg': 'jpg',
  'image/png': 'png',
  'image/webp': 'webp',
  'video/mp4': 'mp4'
};

const storage = multer.diskStorage({
  destination: (req, file, cb) => {
    const year = new Date().getFullYear();
    const month = String(new Date().getMonth() + 1).padStart(2, '0');
    const uploadPath = path.join(__dirname, `../public/uploads/${year}/${month}`);
    cb(null, uploadPath);
  },
  filename: (req, file, cb) => {
    const uniqueSuffix = crypto.randomUUID();
    const ext = ALLOWED_MIME_TYPES[file.mimetype];
    cb(null, `${uniqueSuffix}.${ext}`);
  }
});

const fileFilter = (req, file, cb) => {
  if (ALLOWED_MIME_TYPES[file.mimetype]) {
    cb(null, true);
  } else {
    cb(new Error('نوع الملف غير مدعوم! يسمح فقط بصيغ JPG, PNG, WEBP, MP4.'), false);
  }
};

const upload = multer({
  storage: storage,
  fileFilter: fileFilter,
  limits: { fileSize: 15 * 1024 * 1024 } // الحد الأقصى 15 ميجابايت
});

module.exports = upload;

```

### تكامل الاستيراد الآلي للمحتوى (Automated JSON Ingestion Engine)

1. **الاستقبال والتنقية:** استقبال حزمة الأخبار عبر نقطة التوصيل `/api/v1/admin/ingest/json`.
2. **مطابقة الحقول (Mapping Pipeline):** مطابقة حقول JSON الواردة مع بنية جدول الأخبار:
* `title` -> `articles.title`
* `body` -> `articles.content`
* `category_slug` -> البحث عن `category_id` المقابل في الجدول.


3. **منع التكرار (Deduplication Check):** مقارنة قيمة الـ Slug أو العنوان التراكمي (Hash) لمنع إدخال ذات الخبر مرتين.
4. **معالجة وحفظ الصور:** سحب الصور المرفقة بروابط خارجية وتنظيف البيانات المتاحة ثم تخزين الخبر بحالة default = `draft` أو `published` بحسب صلاحية مصدر الإمداد.

### استراتيجيات تحسين الأداء والأمان (Performance & Security Rules)

#### 1. تحسين الأداء والتخزين المؤقت (Performance & Caching)

* **SQLite Optimization:**
* تفعيل وضع **WAL (Write-Ahead Logging)** لرفع سرعة العمليات والتزامن بين القراءة والكتابة:
`PRAGMA journal_mode = WAL;`
* استخدام الاستعلامات المجهزة مسبقاً (Prepared Statements) للحد من زمن تفسير كود SQL.


* **إستراتيجية Caching لمحتوى الأخبار:**
* استخدام ذاكرة إنتاجية متداخلة في التطبيق (In-Memory Caching مثل `node-cache`) لحفظ نتائج الأخبار الأكثر قراءة والهيكل العام للتصنيفات والتغذية المباشرة لمدة (5 دقائق)، وتقليل الاستعلامات على SQLite بنسبة تصل إلى 80%.


* **الضغط وضغط الوسائط (Gzip / Brotli):**
* تفعيل وحدة `compression` في Express لضغط كافة استجابات JSON وHTML لتقليل استهلاك النطاق الترددي (Bandwidth).



#### 2. تعزيز أمان التطبيق (Application Security Rules)

```javascript
const express = require('express');
const helmet = require('helmet');
const cors = require('cors');
const rateLimit = require('express-rate-limit');

const app = express();

// 1. تعزيز ترويسات الأمان عبر Helmet
app.use(helmet());

// 2. التحكم في سياسة CORS
const corsOptions = {
  origin: process.env.CLIENT_URL || 'https://example.com',
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
  credentials: true
};
app.use(cors(corsOptions));

// 3. حماية حدود الطلبات (Rate Limiting) لمنع هجمات DoS / Bruteforce
const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // نافذة 15 دقيقة
  max: 300, // حد أقصى 300 طلب لكل IP
  message: { error: 'تجاوزت الحد المسموح من الطلبات، يرجى المحاولة لاحقاً.' }
});

app.use('/api/', apiLimiter);

```

* **الحماية من SQL Injection:**
الاعتماد التام على الممر الآمن للمتغيرات (Parameterized Queries) المتاحة عبر محرّك SQLite وعدم دمج النصوص مباشرةً داخل الاستعلامات.
* **الحماية من XSS (Cross-Site Scripting):**
تنقية كود HTML المدخل عبر المحرر الإخباري بـ Backend باستخدام مكتبات التطهير (مثل `sanitize-html`) وتفادي تنفيذ السكريبتات الخبيثة في التعليقات.
* **تأمين البيئة (Environment Variables):**
حفظ مفاتيح التشفير، منافذ الخدمة، ومسارات قواعد البيانات داخل ملف `.dotenv` محمي وخارج النطاق المتاح في Git Repository.
